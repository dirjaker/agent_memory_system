# Agent 记忆系统 — 技术设计文档

> 项目定位：为 AI Agent 提供仿认知科学的六层记忆架构（感觉/短期/工作/长期/情景/语义），支持记忆流转、混合检索（BM25 + 语义向量）、记忆整合压缩和基于艾宾浩斯曲线的自动遗忘机制。

---

## 第一章 项目背景与价值

### 1.1 为什么做

当前主流 AI Agent 面临一个核心痛点：**缺乏结构化的记忆管理能力**。

- LLM 的上下文窗口有限（4K~128K tokens），无法持久保存对话历史
- 多轮对话中 Agent 经常"忘记"之前的交互内容，用户体验差
- 现有方案（如直接拼接历史消息）缺乏对信息重要性的区分，导致关键信息被噪声淹没
- 没有遗忘机制，所有信息同等对待，不符合人类认知规律
- 缺乏情景记忆（对话历史管理）和语义记忆（事实知识图谱）的支持

### 1.2 解决方案

本项目参考认知科学中人类记忆的多阶段模型，设计了一套 **六层记忆架构**：

| 记忆层级 | 容量 | 保留时间 | 对应人类记忆 | 数据结构 |
|---------|------|---------|------------|---------|
| 感觉记忆 | 7±2 项 | < 1 秒 | 视觉/听觉瞬时印象 | `deque(maxlen)` |
| 短期记忆 | 7±2 项 | 几分钟 | 当前意识处理的信息 | `List` |
| 工作记忆 | 20 项 | 当前任务 | 正在加工处理的信息 | `Dict` |
| 长期记忆 | 1000+ 项 | 持久 | 知识、经验、习惯 | `Dict` |
| 情景记忆 | 无上限 | 持久 | 对话历史与事件 | `Dict[session_id, List]` |
| 语义记忆 | 无上限 | 持久 | 事实与知识（三元组） | `Dict` |

### 1.3 面试话术

> "我做了一个 Agent 记忆系统，核心思路是将认知科学的记忆模型应用到 AI Agent 中。系统实现了六层记忆架构——感觉记忆用环形缓冲区缓存输入流，短期记忆保存对话上下文，工作记忆维护当前任务状态，长期记忆通过向量检索存储持久化知识，情景记忆管理对话历史，语义记忆存储事实知识图谱。记忆之间可以自动流转，高重要性的短期记忆会被整合进长期记忆，检索方面支持 BM25 关键词检索和语义向量检索的混合检索，同时系统基于艾宾浩斯遗忘曲线实现了自动衰减机制，让 Agent 能像人一样'记住重要的、忘记无关的'。"

### 2.3 核心数据流

```
用户输入 ──▶ perceive()
              ├── SensoryBuffer.push()    # 感觉记忆（环形缓冲区，自动覆盖旧数据）
              └── ShortTermStore.add()    # 短期记忆（满时淘汰最不重要的）

主动记忆 ──▶ remember(content, importance)
              ├── WorkingMemory.store()   # 工作记忆（满时淘汰最旧的）
              └── LongTermStore.store()   # 条件：importance >= 0.6

查询检索 ──▶ recall(query) / search_memories(query)
              ├── ShortTermStore.search()  # 关键词匹配
              ├── WorkingMemory.search()   # 标签匹配
              ├── LongTermStore.search()   # 综合评分排序
              ├── EpisodicMemory.search()  # 对话历史检索
              └── SemanticMemory.search()  # 事实知识检索
              → 去重 → 按重要性排序 → 返回 Top-K

混合检索 ──▶ HybridRetriever.search()
              ├── BM25Retriever            # 关键词检索（TF-IDF 变体）
              ├── SemanticRetriever        # 语义向量检索
              └── Reranker                 # 重排序
              → RRF 融合 → 返回 Top-K

整合遗忘 ──▶ auto_consolidate() + compress_memory()
              ├── 短期→长期（score >= 阈值）
              ├── 旧记忆按日期分组摘要压缩
              └── 去重器检测并合并重复记忆
```

## 第三章 核心模块设计

### 3.1 MemoryEntry — 记忆条目（memory_store.py）

所有层级共享的统一记忆单元，是整个系统的基础数据结构。

```python
@dataclass
class MemoryEntry:
    """记忆条目"""
    id: str = field(default_factory=lambda: str(uuid.uuid4())[:8])
    content: str = ""
    metadata: Dict[str, Any] = field(default_factory=dict)
    embedding: List[float] = field(default_factory=list)  # 向量嵌入
    importance: float = 0.5  # 重要性分数 0-1
    access_count: int = 0    # 访问次数
    created_at: datetime = field(default_factory=datetime.now)
    last_accessed: datetime = field(default_factory=datetime.now)
    tags: Set[str] = field(default_factory=set)

    def access(self):
        """记录访问（复述增强记忆）"""
        self.access_count += 1
        self.last_accessed = datetime.now()

    def decay(self, hours: float = 24.0) -> float:
        """
        计算记忆衰减后的分数
        基于艾宾浩斯遗忘曲线：score = importance × 2^(-t/T_half)
        """
        time_since_access = (datetime.now() - self.last_accessed).total_seconds() / 3600
        half_life = hours
        decay_factor = 2 ** (-time_since_access / half_life)
        return self.importance * decay_factor
```

**设计要点：**
- 使用 `uuid4()[:8]` 生成短 ID，兼顾唯一性和可读性
- `decay()` 方法实现艾宾浩斯遗忘曲线：`score = importance × 2^(-t/T_half)`，其中半衰期可通过参数调整
- 每次 `access()` 都会刷新 `last_accessed`，实现"复述增强记忆"效果
- `to_dict()` 支持序列化输出，便于调试和 API 响应

### 3.2 SensoryBuffer — 感觉记忆（memory_store.py）

模拟人类的瞬时感觉记忆，使用环形缓冲区实现，容量极小、自动覆盖。

```python
class SensoryBuffer:
    def __init__(self, capacity: int = 7):
        self.capacity = capacity
        self.buffer = deque(maxlen=capacity)

    def push(self, content: str, metadata: Dict = None) -> MemoryEntry:
        entry = MemoryEntry(content=content, metadata=metadata or {}, importance=0.1)
        self.buffer.append(entry)
        return entry

    def get_all(self) -> List[MemoryEntry]:
        return list(self.buffer)

    def clear(self):
        self.buffer.clear()
```

**设计要点：**
- 使用 `collections.deque(maxlen=capacity)` 实现环形缓冲区，超出容量自动丢弃最旧数据
- 感觉记忆重要性固定为 0.1，保证不会被误判为重要信息
- 7±2 容量符合认知科学中的 Miller's Law（米勒定律）

### 3.3 ShortTermStore — 短期记忆（memory_store.py）

保存当前对话上下文，支持关键词搜索，满时淘汰最不重要的记忆。

```python
class ShortTermStore:
    def __init__(self, capacity: int = 7):
        self.capacity = capacity
        self.memories: List[MemoryEntry] = []

    def add(self, content, importance=0.5, tags=None) -> MemoryEntry:
        entry = MemoryEntry(content=content, importance=importance, tags=tags or set())
        if len(self.memories) >= self.capacity:
            self._evict()  # 淘汰最不重要的
        self.memories.append(entry)
        return entry

    def search(self, query: str) -> List[MemoryEntry]:
        """大小写不敏感的关键词搜索"""
        query_lower = query.lower()
        return [m for m in self.memories if query_lower in m.content.lower()]
```

**设计要点：**
- 淘汰策略：按重要性排序，移除分数最低的（而非最旧的），保护关键信息
- 搜索基于 `str.lower()` 的大小写不敏感匹配，简单高效

### 3.4 WorkingMemory — 工作记忆（memory_store.py）

管理当前任务相关的活跃信息，使用 Dict 存储支持 O(1) 的 ID 检索。

```python
class WorkingMemory:
    def __init__(self, capacity: int = 20):
        self.capacity = capacity
        self.memories: Dict[str, MemoryEntry] = {}
        self.current_context: List[str] = []

    def store(self, content, importance=0.6, tags=None) -> MemoryEntry:
        entry = MemoryEntry(content=content, importance=importance, tags=tags or set())
        if len(self.memories) >= self.capacity:
            self._evict()  # LRU 淘汰最旧的
        self.memories[entry.id] = entry
        return entry

    def get_context(self, limit: int = 5) -> str:
        """按最后访问时间排序，返回最近的 N 条记忆"""
        recent = sorted(self.memories.values(), key=lambda m: m.last_accessed, reverse=True)[:limit]
        return "\n".join([m.content for m in recent])

    def search_by_tags(self, tags: Set[str]) -> List[MemoryEntry]:
        """根据标签集合搜索"""
        return [m for m in self.memories.values() if m.tags.intersection(tags)]
```

**设计要点：**
- 使用 `Dict[str, MemoryEntry]` 存储，支持 O(1) 的 ID 检索
- `get_context()` 按最后访问时间排序，返回最近的 N 条记忆作为上下文
- 淘汰策略：移除最旧的（LRU），与短期记忆的重要性淘汰形成互补

### 3.5 LongTermStore — 长期记忆（memory_store.py）

持久化存储知识和经验，支持综合评分的搜索和自动遗忘。

```python
class LongTermStore:
    def __init__(self, max_size: int = 1000):
        self.max_size = max_size
        self.memories: Dict[str, MemoryEntry] = {}

    def search(self, query: str, limit: int = 5) -> List[MemoryEntry]:
        results = []
        query_lower = query.lower()
        for mem in self.memories.values():
            relevance = 0.0
            if query_lower in mem.content.lower():
                relevance = 0.8
            elif any(tag in query_lower for tag in mem.tags):
                relevance = 0.6
            if relevance > 0:
                freshness = mem.decay()
                score = relevance * 0.6 + mem.importance * 0.2 + freshness * 0.2
                results.append((score, mem))
        results.sort(key=lambda x: x[0], reverse=True)
        return [mem for _, mem in results[:limit]]

    def _forget(self):
        """容量达到 90% 时清理综合分数最低的 10%"""
        if len(self.memories) < self.max_size * 0.9:
            return
        scored = []
        for mem in self.memories.values():
            score = mem.importance * 0.5 + mem.decay() * 0.3 + min(mem.access_count / 10, 0.2)
            scored.append((score, mem.id))
        scored.sort()
        remove_count = max(1, len(scored) // 10)
        for _, mem_id in scored[:remove_count]:
            del self.memories[mem_id]
```

**设计要点：**
- 搜索使用三因子综合评分：`相关性(60%) + 重要性(20%) + 新鲜度(20%)`
- 遗忘触发条件：容量达到 90% 时开始清理，移除综合分数最低的 10%
- 遗忘综合分数公式：`importance × 0.5 + decay() × 0.3 + min(access_count/10, 0.2)`
  - 被频繁访问的记忆获得额外保护（access_count 权重上限 0.2）

### 3.6 EpisodicMemory — 情景记忆（memory_store.py）

```python
class DialogueTurn:
    """对话轮次"""
    session_id: str
    role: str          # "user" / "assistant" / "system"
    content: str
    timestamp: datetime
    metadata: Dict[str, Any]

class EpisodicMemory:
    """情景记忆 — 按会话管理对话历史"""

    def __init__(self):
        self.sessions: Dict[str, List[DialogueTurn]] = {}

    def add_turn(self, session_id, role, content, metadata=None) -> DialogueTurn:

        self.sessions.setdefault(session_id, []).append(turn)
        return turn

    def get_session_history(self, session_id, limit=50) -> List[DialogueTurn]:
        return self.sessions.get(session_id, [])[-limit:]

    def search(self, query, limit=10) -> List[DialogueTurn]:
        """在所有会话中搜索包含关键词的对话轮次"""
```

### 3.8 MemoryManager — 记忆管理器（memory_manager.py）

统一管理六层记忆的核心类，提供高层 API 并协调记忆流转。

```python
class MemoryManager:
    """统一管理六层记忆系统"""

    def __init__(self, sensory_capacity=7, short_term_capacity=7,
                 working_capacity=20, long_term_capacity=1000):
        # 六层记忆
        self.sensory = SensoryBuffer(capacity=sensory_capacity)
        self.short_term = ShortTermStore(capacity=short_term_capacity)
        self.working = WorkingMemory(capacity=working_capacity)
        self.long_term = LongTermStore(max_size=long_term_capacity)
        self.episodic = EpisodicMemory()
        self.semantic = SemanticMemory()
        # 辅助组件
        self.consolidator = MemoryConsolidator()
        self.consolidation_threshold = 0.6
```

**核心 API：**

| 方法 | 说明 |
|------|------|
| `perceive(content, metadata)` | 感知输入，双写感觉记忆 + 短期记忆 |
| `remember(content, importance, tags)` | 主动记忆，高重要性自动写入长期记忆 |
| `recall(query, limit)` | 回忆检索，跨层级搜索后去重排序 |
| `search_memories(query, limit)` | 混合检索，BM25 + 语义向量融合 |
| `add_episodic(session_id, role, content)` | 添加情景记忆 |
| `add_semantic(fact, entities)` | 添加语义记忆 |
| `get_context(limit)` | 获取上下文（工作记忆 + 短期记忆） |
| `get_context_for_llm(query, limit)` | 为 LLM 生成结构化上下文 |
| `auto_consolidate()` | 自动整合记忆（短期 → 长期） |
| `compress_memory(days)` | 压缩旧记忆 |
| `save_to_db(path)` / `load_from_db(path)` | SQLite 持久化 |
| `get_observability_report()` | 获取可观测性报告 |

**设计要点：**
- `perceive()` 实现双写：感觉记忆 + 短期记忆，模拟人类"注意"过程
- `remember()` 实现条件分流：importance >= 0.6 时同时写入长期记忆
- `recall()` 实现跨层级搜索：短期(关键词) → 工作(标签) → 长期(综合评分) → 情景 → 语义，最终去重排序
- `search_memories()` 使用混合检索器，融合 BM25 和语义检索结果
- 向后兼容 v1.x API：perceive / remember / recall / get_context / consolidate / forget 全部保留

### 3.9 MemoryConsolidator — 记忆整合器（memory_consolidator.py）

负责记忆的整合、压缩和质量评估。

```python
class MemoryConsolidator:
    """记忆整合器"""

    def __init__(self, embedding=None, llm_client=None):
        self.scorer = RuleBasedImportanceScorer()  # 或 LLMImportanceScorer
        self.embedding = embedding

    def score_importance(self, content, context="") -> float:
        """评估记忆重要性（LLM 或规则降级）"""

    def summarize(self, memories: List[MemoryEntry]) -> str:
        """将多条记忆压缩为摘要"""

    def deduplicate(self, memories, threshold=0.8) -> List[MemoryEntry]:
        """检测并合并重复记忆"""

    def consolidate_short_to_long(self, short_term, long_term, threshold=0.6):
        """整合短期记忆到长期记忆"""

    def compress_old_memories(self, long_term, days=7):
        """压缩旧记忆（按日期分组摘要）"""
```

**重要性评分策略（策略模式）：**

| 评分器 | 说明 |
|--------|------|
| `BaseImportanceScorer` | 抽象基类 |
| `RuleBasedImportanceScorer` | 基于规则：关键词检测、内容长度、数字密度等 |
| `LLMImportanceScorer` | 基于 LLM：调用大语言模型评估重要性 |

**设计要点：**
- 策略模式支持 LLM 和规则两种评分方式，无 LLM 时自动降级为规则模式
- 去重使用编辑距离（Levenshtein）计算文本相似度
- 压缩按日期分组，对旧记忆生成摘要后替换原始条目

### 3.10 HybridRetriever — 混合检索器（retriever.py）

提供多种检索策略，支持关键词检索、语义检索和混合检索。

```python
@dataclass
class RetrievalResult:
    """统一的检索结果格式"""
    content: str
    score: float
    source: str = ""          # 来源标识（"long_term" / "episodic" / "semantic" 等）
    metadata: Dict[str, Any] = {}

class BM25Retriever:
    """BM25 关键词检索器（Okapi BM25 算法）"""
    def search(self, query, memories, top_k=10) -> List[RetrievalResult]

class SemanticRetriever:
    """语义向量检索器"""
    def search(self, query, memories, top_k=10) -> List[RetrievalResult]

class HybridRetriever:
    """混合检索器 — 融合 BM25 + 语义（RRF 融合）"""
    def search(self, query, memories, top_k=10) -> List[RetrievalResult]

class Reranker:
    """重排序器 — 基于查询相关性重新排序"""
    def rerank(self, query, results, top_k=10) -> List[RetrievalResult]
```

**BM25 评分公式：**
```
score(Q, D) = Σ IDF(qi) · (f(qi, D) · (k1 + 1)) /
               (f(qi, D) + k1 · (1 - b + b · |D| / avgdl))
```

**设计要点：**
- BM25 是 TF-IDF 的改进变体，通过对词频进行饱和处理和文档长度归一化来提升检索质量
- RRF（Reciprocal Rank Fusion）融合关键词和语义两路检索结果
- 纯 Python 实现 BM25，无外部依赖

## 第四章 技术亮点

### 4.1 认知科学驱动的架构设计

系统基于 Atkinson-Shiffrin 记忆模型（1968）和 Baddeley 工作记忆模型（1974），并扩展了情景记忆和语义记忆：

| 认知模型 | 系统实现 | 容量 | 淘汰策略 | 搜索方式 |
|---------|---------|------|---------|---------|
| 感觉记忆 | SensoryBuffer | 7±2 | 自动覆盖（环形缓冲区） | 全量遍历 |
| 短期记忆 | ShortTermStore | 7±2 | 重要性最低者淘汰 | 关键词匹配 |
| 工作记忆 | WorkingMemory | 20 | LRU 最旧淘汰 | 标签匹配 |
| 长期记忆 | LongTermStore | 1000 | 综合分数最低 10% | 三因子评分 |
| 情景记忆 | EpisodicMemory | 无上限 | — | 关键词搜索 |
| 语义记忆 | SemanticMemory | 无上限 | — | 实体搜索 |

### 4.2 艾宾浩斯遗忘曲线的工程实现

```python
decay_factor = 2 ** (-time_since_access / half_life)
score = importance * decay_factor
```

- 半衰期可配置（默认 24 小时），不同场景可调
- 结合 `access_count` 实现"复述增强"——被频繁访问的记忆衰减更慢
- 遗忘不是简单的 TTL 过期，而是渐进式衰减，更符合人类记忆特征

### 4.3 多因子综合评分

长期记忆的搜索和遗忘都使用多因子评分，避免单一维度的偏差：

| 因子 | 搜索权重 | 遗忘权重 | 含义 |
|------|---------|---------|------|
| 相关性 | 60% | — | 查询与内容的匹配度 |
| 重要性 | 20% | 50% | 用户标注的重要性 |
| 新鲜度 | 20% | 30% | 艾宾浩斯衰减后的分数 |
| 访问频率 | — | 20% | 被回忆的次数 |

### 4.4 混合检索引擎

融合 BM25 关键词检索和语义向量检索，通过 RRF（Reciprocal Rank Fusion）算法融合两路结果：

- **BM25**：擅长精确匹配，对关键词查询效果好
- **语义检索**：擅长语义理解，对模糊查询效果好
- **RRF 融合**：`score = Σ 1/(k + rank_i)`，综合两路排名
- **Reranker**：对融合结果进行二次排序，提升最终质量

### 4.5 Embedding 抽象层

通过策略模式支持多种嵌入方案，通过工厂函数自动降级：

```
SentenceTransformer（最优）
    ↓ 不可用时自动降级
OpenAI Embedding（需 API Key）
    ↓ 不可用时自动降级
TF-IDF（需 sklearn）
    ↓ 不可用时自动降级
Hash Embedding（零依赖，始终可用）
```

### 4.6 零外部依赖的核心设计

核心记忆模块（`memory_store.py`、`memory_manager.py`）仅使用 Python 标准库。这让系统可以轻松集成到任何 Python 项目中，无需额外安装依赖。

## 第五章 面试常见问题

### Q1: 为什么选择六层记忆而不是简单的 Key-Value 存储？

**A:** 简单的 KV 存储无法区分信息的重要性和时效性。六层记忆模拟了人类认知过程：感觉记忆过滤噪声、短期记忆保持对话连贯、工作记忆聚焦当前任务、长期记忆沉淀知识、情景记忆管理对话历史、语义记忆存储事实。每一层有不同的容量、淘汰策略和搜索方式，使 Agent 能像人一样"分层处理"信息。

### Q2: 遗忘机制的设计思路是什么？为什么不是简单的 TTL？

**A:** 简单 TTL 会导致信息突然消失，不符合人类记忆的渐进衰减特征。我采用了艾宾浩斯遗忘曲线的简化版本——`score = importance × 2^(-t/T_half)`，记忆会随时间逐渐"淡化"而非突然"删除"。同时结合了访问频率因子，被反复回忆的记忆会获得更强的保持力（类似人类的"间隔重复"学习法）。淘汰时移除的是综合分数最低的 10%，而非最旧的，这样既保证了重要记忆的持久性，又避免了内存无限增长。

### Q3: 混合检索是如何工作的？

**A:** `HybridRetriever` 内部维护 BM25 和语义两路检索器。BM25 使用 TF-IDF 变体进行关键词匹配，擅长精确查询；语义检索使用 Embedding 向量计算余弦相似度，擅长语义理解。两路结果通过 RRF（Reciprocal Rank Fusion）算法融合——`score = Σ 1/(k + rank_i)`，最后由 Reranker 进行二次排序。这种设计兼顾了精确匹配和语义理解的需求。

### Q4: Embedding 抽象层的设计考虑是什么？

**A:** 使用策略模式定义 `BaseEmbedding` 抽象基类，支持 `embed_text()` 和 `embed_batch()` 两个核心方法。通过工厂函数 `create_embedding()` 创建实例，支持"auto"模式自动降级：优先使用 SentenceTransformer，不可用时降级到 OpenAI，再降级到 TF-IDF，最终降级到零依赖的 Hash 嵌入。这确保了系统在任何环境下都能运行。

### Q5: 情景记忆和语义记忆的区别是什么？

**A:** 情景记忆（EpisodicMemory）管理对话历史，按会话组织，存储的是"谁在什么时候说了什么"这类事件信息。语义记忆（SemanticMemory）存储事实知识，以三元组（主语-谓语-宾语）形式组织，存储的是"Python 是一种编程语言"这类客观知识。两者互补：情景记忆帮助 Agent 回忆过去的交互，语义记忆帮助 Agent 回答知识性问题。

### Q6: 记忆整合（consolidate）的时机和策略是什么？

**A:** `auto_consolidate()` 需要手动或定期调用。它遍历短期记忆，计算综合分数 `importance × 0.7 + access_count × 0.3`，超过阈值（0.6）的会被复制到长期记忆。同时会触发去重（检测相似记忆）和压缩（按日期分组摘要旧记忆）。访问次数的权重保证了被反复回忆的记忆更容易被"巩固"到长期记忆中。

### Q7: 如何将这个系统集成到实际的 LLM Agent 中？

**A:** 集成方式：
1. 在 Agent 收到用户消息时调用 `perceive(content)`
2. 在 Agent 提取关键信息时调用 `remember(content, importance, tags)`
3. 在构造 LLM prompt 时调用 `get_context_for_llm(query)` 获取结构化上下文
4. 在需要相关知识时调用 `search_memories(query)` 混合检索
5. 定期调用 `auto_consolidate()` 和 `compress_memory()` 维护记忆健康度
6. 通过 `save_to_db()` / `load_from_db()` 实现持久化
